# Gap Audit — eravos-static-apache-3

Zoom-level sweep: architecture → JSON/asset integrity → static wiring →
full runtime click-through (jsdom, real HTTP server, every tab/category/
settings-subtab) → targeted fix verification. All tests re-run clean
after the patch below.

## Fixed

**Header 🔔 and 💌 buttons were dead wires.** `onclick="openNotificationInbox()"`
and `onclick="openCommHub()"` called functions that didn't exist anywhere
in the codebase — clicking either threw a silent `ReferenceError` and did
nothing. Root cause matches the "declared wire, not implemented" pattern:
a fully-built inbox system (`eravors_inbox`, `renderInbox`, `updateInboxBadge`,
`markRead`/`markAllRead`) already lived inside the Messages tab, and a
fully-built partner-reach system already lived in the Poke tab — the
header just never got connected to either.

Fix (in `shared/eravos-kernel.js`, ~10 lines, zero new UI):
- `openNotificationInbox()` → lazy-mounts and switches to the existing
  Messages tab (same path real tab-nav clicks use).
- `openCommHub()` → lazy-mounts and switches to the existing Poke tab.
- `updateInboxBadge()` now also syncs the header `#notif-badge`, which
  previously never updated and would have sat on "0" forever.
- The already-dispatched-but-unlistened `eravos:mounted` event now has
  one listener: sync the header badge on boot, so unread count is
  correct on load instead of only after visiting Messages once.

Chose reuse over new construction on purpose — highest leverage per line
changed, and zero new untested surface area.

## Checked, no action needed

- Kernel + all 25 tab/subtab inline scripts: syntax-clean (`node --check`).
- All `contracts/*.json`, `manifest.json`, `config/options.json`: valid JSON.
- All static `href`/`src` references resolve over real HTTP.
- Zero duplicate DOM `id`s across the full mounted app (426 scanned).
- Full runtime sweep: booted in jsdom against a live server, clicked
  every one of 24 tabs, 5 categories, 5 settings subtabs — 0 window
  errors, 0 console errors, before and after the patch.
- `sc-space` / `sc-projects` / `sc-ideas` / `sc-vault` / `sc-threads` /
  `sc-people` / `sc-nodes` ("Community" category) — real, but not a bug.
  `TAB_NAMES` and `TAB_CATEGORY` in the kernel declare these; no nav
  button, no tab file, no contract exists for any of them. Manifest
  already flags this honestly (`community_UNWIRED`). Confirmed
  non-crashing (dead code, never dispatched) but this is a whole
  unbuilt feature, not a fillable gap — needs a design pass (what is
  "Community" here, whose data, what UI) before it's buildable. Flagging
  rather than guessing an implementation.
- Single global scope is intentional per the kernel's own header comment
  — contracts document call graphs for future per-tab modularization,
  not a runtime defect.

## Method

`node --check` on every inline script + kernel · JSON validation ·
static asset resolution over real HTTP · jsdom + native `fetch` against
a live `python3 -m http.server` instance, full DOM event simulation
(not just static analysis) for every nav path · targeted before/after
tests on the two fixed functions confirming actual DOM state, not just
absence of errors.
